## Versioning in S3

- Versioning is an S3 feature that allows you to keep multiple versions of an object in the same bucket. 
- Each version of the object has a unique version ID, which is a string that is generated by S3. 
- When you upload a new version of an object, S3 automatically generates a new version ID for that object. 
- You can also use versioning to protect your data against accidental deletion or overwrite.

## Benefits of S3 versioning

- Protect against accidental deletion: With versioning enabled, you can protect your data against accidental deletion. If you delete an object, S3 does not delete the object, but instead adds a delete marker to the object. The delete marker indicates that the object has been deleted, but the object and its versions are still stored in the bucket.
- Rollback to previous versions: With versioning enabled, you can rollback to previous versions of an object. If you overwrite an object, S3 automatically creates a new version of the object, allowing you to rollback to the previous version if necessary.
- Compliance: Versioning helps you comply with regulations and policies that require you to keep multiple versions of an object.
- Simplified backup and recovery: With versioning, you can simplify backup and recovery by storing all versions of an object in the same bucket. This eliminates the need to create multiple buckets or use a separate backup system.

## How to enable versioning

You can enable versioning for an S3 bucket using the AWS Management Console or the AWS CLI.

### Enable versioning with the AWS Management Console

- Open the S3 console.
- Select the bucket for which you want to enable versioning.
- Choose Properties from the top menu.
- Choose Versioning.
- Choose Enable versioning.
- Click Save.

### Enable versioning with the AWS CLI

- Enter the following command to enable versioning

`aws s3api put-bucket-versioning --bucket your-bucket-name --versioning-configuration Status=Enabled`

## How to manage versions

You can manage versions of objects in an S3 bucket using the AWS Management Console or the AWS CLI.

### Manage versioning with the AWS Management Console

- Select the bucket that contains the object for which you want to manage versions.
- Choose the object.
- Choose Versions from the top menu.
- Choose the version of the object that you want to manage.
- Choose the appropriate action, such as Delete or Restore.

### Manage versioning with the AWS CLI

- Open a terminal or command prompt.
- Enter the following command to list all versions of an object

`aws s3api list-object-versions --bucket your-bucket-name --prefix your-object-name`

- Enter the following command to delete a specific version of an object

`aws s3api delete-object --bucket your-bucket-name --key your-object-key --version-id your-version-id`


### Some additional AWS CLI commands for versioning

- List all versions of all objects in an S3 bucket.
  `aws s3api list-object-versions --bucket bucket-name`

- Upload a specific version of an object to S3 bucket.
  `aws s3api put-object --bucket bucket-name --key key-name --body file.txt --version-id 1234567890abcdefg`

- Delete a specific version of an object from an S3 bucket.
  `aws s3api delete-object --bucket bucket-name --key key-name --version-id 1234567890abcdefg`

- List all versions of objects in a specific folder in an S3 bucket
  `aws s3api list-object-versions --bucket bucket-name --prefix folder/`

- Limit the number of versions of objects returned in the list to 10.
  `aws s3api list-object-versions --bucket bucket-name --max-items 10`

- Retrieve a specific version of an object from an S3 bucket
  `aws s3api get-object --bucket bucket-name --key key-name --version-id 1234567890abcdefg`

## Lifecycle policies for versioning

- Amazon S3 allows you to create lifecycle policies to automatically expire or delete old object versions
- This helps to keep your storage usage and costs under control

You can create a lifecycle policy using the AWS Management Console or the AWS CLI.

- Open the Amazon S3 console and navigate to the bucket for which you want to create a lifecycle policy.
- Click on the "Management" tab and then click on "Lifecycle".
- Click on "Add lifecycle rule" and give a name to your rule.
- Choose the object prefix to which you want the rule to apply.
- Select the action you want to take on the object versions that match the prefix, such as expire or delete.
- Configure the expiration or deletion settings for the object versions.
- Add any additional rules if needed and click on "Review".
- Review your settings and click on "Create rule".

Here are the steps to create a lifecycle policy using the AWS CLI:

- Create a policy.json file

    ```json
    {
    "Rules": [
        {
        "Filter": {
            "Prefix": "prefix/"
        },
        "Status": "Enabled",
        "NoncurrentVersionExpiration": {
            "NoncurrentDays": 30
        }
        }
    ]
    }'
    ```

- Use the command to apply the policy
   `aws s3api put-bucket-lifecycle-configuration --bucket bucket-name --lifecycle-configuration file://policy.json`
